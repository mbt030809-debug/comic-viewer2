# 워터마크 인식 재설계 플랜 wm2 (2026-11-21)

범위: **인식만**. 제거(WmModel.clean 등)는 건드리지 않고, 인식 결과를 어댑터로 넘긴다.
기존 `PLAN_wm_recognition_20261121.md`의 §1~3(정답지·측정·실패 분류)은 그대로 쓰고, §4(종류별 접근)는 이 문서로 대체한다.

## 1. 왜 지금 코드가 꼬였나 (진단)
1. **'반복'과 '워터마크'를 구분하지 못한다.** 축소 윤곽 쌍 NCC는 컷 테두리, 화면 요소, 중복 이미지도 똑같이 반복으로 본다. 그래서 오인식 원인이 나올 때마다 땜질이 쌓였다(`suppressFrames`, `houghKill`, `calm`, `markShape`, 중복 제거, `PRES_MIN`).
2. **위치 가설이 하드코딩돼 있다.** TL/BL/F25/F50/F75/FREE마다 파이프라인이 따로 있다. 새 종류가 나오면 줄이 늘어난다.
3. **한 번에 결정하고 못 바꾼다.** `active == null`일 때만 감지하고, 첫 모델이 틀려도 뒤집지 못한다(기기 시험에서 낡은 모델이 찾기를 막은 버그와 같은 구조). 결과가 이미지 순서·표본에 흔들린다.
4. **인식·모델 학습·지우기가 한 클래스(WmModel)에 섞여 있다.** 인식만 따로 시험하거나 바꿀 수 없다.
5. **축소 윤곽(s=1~8)만 쓴다.** 연한 도장(α≈0.2)의 신호가 축소 과정에서 사라진다.

## 2. 새 방법론: 합의 템플릿 추정
**관측 모델**: `J_k = (1-α(x-p_k))·I_k + α(x-p_k)·W(x-p_k)`
- `I_k`: 장마다 다른 배경 그림. `(α, W)`: 모든 장에 공유되는 워터마크. `p_k`: 장마다의 위치(자세).
- 원리(Dekel 등, CVPR 2017 "On the Effectiveness of Visible Watermarks"): 정렬된 여러 장의 **부호 있는 기울기(gx, gy)의 픽셀별 중앙값**을 구하면 배경 기울기는 서로 상쇄돼 사라지고 워터마크 기울기만 남는다.
- "반복되는 곳 찾기"가 아니라 **"모든 장이 공유하는 층을 추정하고, 그 추정이 믿을 만한지 통계로 잰다"**로 바꾼다.

### 2.1 하나의 파이프라인(위치 종류 통합)
- 위치 `p_k` = 앵커 + 이동량. 앵커(왼쪽 위, 왼쪽 아래, 높이 비율)는 **별개 파이프라인이 아니라 좌표계 후보**일 뿐이다. 고정형은 이동량 사전분포가 점이고, 흔들림형(FREE)은 y에 대해 균등분포다.
- 반복 추정(정렬, congealing 방식): 초기 자세 → 중앙값 템플릿 T → 장마다 마스크 NCC로 자세 재탐색 → T 재추정. 몇 번 돌려 수렴시킨다.
- 시드: (a) 앵커별 이동량 0, (b) 쌍 단위 거친 탐색(기존 `searchPair` 재사용, 흔들림형용).
- 후보는 **가설 장부(HypothesisBook)**에 여러 개를 동시에 두고 증거로 경쟁시킨다. 먼저 잡힌 모델이 이기는 게 아니라 증거가 많은 모델이 이긴다.

### 2.2 증거 = 보정된 통계(NCC 임계값 대신)
- **귀무 분포**: 같은 템플릿 T를 다른 위치와 다른 장에 맞춰 얻은 응답으로 만든다. 후보 점수는 이 분포 기준의 z값이다.
- **분할 신뢰도(split-half)**: 장을 반으로 나눠 각각 템플릿을 추정하고 서로 일치하는지 잰다. 반복성을 직접 재는 값이라 임계값 땜질이 필요 없다.
- **누적 판정(SPRT식)**: 이미지가 들어올 때마다 로그우도비를 더한다. 순서와 무관하고, 증거가 부족하면 **"불확실"**을 내고 추측하지 않는다. 장 수가 3~4장 이하이거나 장들이 같은 그림이면 판정하지 않는다.

### 2.3 오인식 원인을 후처리 필터가 아니라 가설로 처리
| 반복 원인 | 처리 |
|---|---|
| 직선(컷 테두리, 구분선) | 중앙값 맵의 선형 성분을 **방해층으로 먼저 적합해 빼고**(1차원 투영) 추정한다. 모든 이미지에 허프 변환을 돌리지 않는다 |
| 같은 이미지 중복 | 지각 해시로 제거(유지) |
| 화면 요소(스크린샷만) | 앱은 실제 이미지 바이트를 가로채므로 실사용에선 없음. 스크린샷 시험은 앱 화면을 잘라낸 `real_crop_all`만 쓴다 |
| 진짜 워터마크 | 지지영역(support)이 **한 덩어리로 작고**, 여러 방향 윤곽을 갖고, **배경이 다른 장들에서도 일치**함(분할 신뢰도) |

### 2.4 해상도
- **거친 탐색은 축소본, 템플릿 추정과 확인은 원본 해상도의 후보 주변 잘라낸 조각**에서 한다. 연한 α 신호를 보존하고 상자를 정확히 잡는다.
- 상자는 NCC 덩어리가 아니라 **원본 해상도 중앙값 기울기 에너지의 지지영역**(닫힘 연산 포함)으로 정한다. 지금 문제인 "상자가 실제보다 큼"을 구조적으로 해결한다.

### 2.5 종류별 확장
- 고정형(1화): 이동량 0, 앵커 경쟁.
- 흔들림형(2화): 자세 반복 추정.
- 전면 반복 무늬(3화): 중앙값 맵의 자기상관 봉우리로 주기를 찾는다. 모델은 타일 1개 + 격자 벡터이고 지지영역은 이미지 전체다.
- 크기가 제각각(4화): 자세에 배율 축소 탐색을 추가한다(가장 마지막).
- 한 이미지에 도장 2개: 1번째를 마스크한 뒤 2차 패스.
- (보류) 학습형 단일 이미지 히트맵 사전분포: 학습에 PC·GPU가 필요해서 지금은 하지 않는다.

## 3. 구조(코드 정리)
새 패키지 `com.example.comicviewer.wm2`를 **옆에 병행으로** 만든다. 순수 Kotlin/JVM이라 이 폰의 `kc`로 시험할 수 있다(안드로이드 의존 없음). 설정 `wmEngine=2`로 전환하고, 새 엔진이 기준을 넘으면 옛 코드를 지운다.
- `Prep`: 회색조·기울기 피라미드, 중복 해시, 단색 판정
- `Pose`: 앵커 + 이동량(+배율)
- `Estimator`: 정렬된 중앙값 기울기, 지지영역, 분할 신뢰도
- `Locator`: 마스크 NCC 거칠게→세밀하게
- `Evidence`: 귀무 분포 z값, 누적 판정
- `HypothesisBook`: 가설 장부(승격·강등, 일회성 관문 없음)
- `Recognition`(출력): `{템플릿 gx/gy, 지지영역, 장별 자세, 신뢰도, 종류, 판정 사유}`. 지우기와 무관한 순수 데이터다.
- `Adapter`: Recognition → 기존 `WmModel`(`buildModel`) 변환. 지우기 코드는 당분간 그대로 쓴다.
- 진단: 가설마다 한 줄(z값, 분할 신뢰도, 지지영역 통계, 탈락·불확실 사유). `WmDiag` 태그 유지.

## 4. 측정(기존 §2에 더해)
- 기존 유지: 눈으로 쓴 정답지, IoU≥0.5, seed 7(수정용)/seed 11(검증용), `real_crop_all` 회귀, 순서·표본 흔들기.
- **추가 ①: 무작위 사이트 대량 시험**. 생성기를 확장해 워터마크 종류(글자·로고·원형·타일)·α(0.15~1)·크기·앵커·흔들림을 무작위로 뽑은 사이트 200개 정도에서 맞음/놓침/오인식 **분포**를 본다. 6화짜리 손으로 만든 사례에 맞추는 걸 막는다.
- **추가 ②: 워터마크 없는 사이트**를 반드시 넣어 오인식률을 잰다(현재 D 4/14).
- **추가 ③: 순서 안정성**: 같은 사이트를 임의 순서·부분집합으로 20번 돌려 판정 일치율을 본다(목표 ≥95%).
- 실패는 매번 (a) 후보 없음 (b) 밀림 (c) 상자 범위 (d) 위치 찾기로 자동 분류해 표로 낸다.
- **전환 기준**: 새 엔진이 FF 15/0/9 이상, 합성 6화 중 현재 이상, 워터마크 없는 사이트 오인식 ≤ 현재, 순서 안정성 ≥95%.

## 6. 위험·한계
- **한 화에만 통하는 땜질 금지**: 고치는 것은 원리 수준이어야 하고, seed 11과 무작위 사이트에서 같이 좋아져야 한다.
- 판정할 수 없는 경우(장 수 부족, 배경 동일)는 **"불확실"을 낸다**. 추측해서 점을 찍지 않는다.
- 실행 시간·메모리: 원본 해상도 조각은 후보 주변만, 최대 8장. 거친 탐색은 축소본. P1에서 폰 실측한다.
- 이 폰의 시험은 합성 시험이다. 실기기 결과와 구분해 보고한다.
