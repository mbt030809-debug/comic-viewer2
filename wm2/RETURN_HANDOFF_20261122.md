# wm2 귀환 핸드오프 — PC 학습 결과 (2026-11-22)

원본: `wm2/HANDOFF_PC_TRAIN_20261121.md`. 결과 파일: 브랜치 `wm2-pc-results`의 `wm2/results/20261122/`. 모든 수치는 **합성 벤치**(PC 글꼴로 생성, 폰 벤치와 다름)이며 실제 웹툰·폰 CPU는 검증하지 않았다.

## 1. 한 줄 결론
U-Net 0.95M(채널 2배)를 하드 네거티브 합성기로 34k 스텝 학습하면 core 인식률 84.0%, wild 음성 오인식 1.8%까지 가지만, core 음성 오인식은 7.1%로 목표(≤5%)에 못 미치고 정밀도(core 34%)가 낮아 앱에는 "여러 장 반복 위치 채택" 같은 방어가 필요하다.

- **학습량이 1차 병목**: 3k→10k에서 core 음성 오인식 69.8%→17.5%. 이후 14k를 더해도(A→A+14k) 인식률 +1~2%p, 음성 오인식 변화 없음 → 학습량 수확이 거의 끝남.
- **용량**: 0.24M→0.95M은 약간 도움(17.5→7.9%), 3.79M은 0.95M과 같음 → 0.95M으로 충분.
- **하드 네거티브(synth2)**: wild 음성 오인식(12.5→1.8%)과 ambiguous 오인식(43~53→0%)을 크게 줄이는 대신 인식률이 core 약 9%p, wild 약 7%p 낮아진다(A vs B, 같은 스텝).
- **한 장 한계**: 말풍선·글자와 글자형 워터마크를 한 장만으로 구분하는 어려움은 학습량으로 해소되지 않았다(정밀도 core 34%, wild 21%). 가설일 뿐 별도 실험은 하지 않았다.
- **val**(최종 후보 1회만 평가): 인식률 73.0%, 음성 오인식 0.0%(0/21), ambiguous 0%, 정밀도 20.4%. core 대비 인식률이 11%p 낮다(wild와 비슷).
- 목표(§6) 대비: core 인식률 ≥80% **달성(84.0%)**, 음성 오인식 ≤5% core **미달(7.1%)** / wild **달성(1.8%)**, wild·val 인식률은 core보다 낮다(74.5% / 73.0%).

## 3. 추천 모델
- 파일: `wm2/results/20261122/wm2_unet_ch2_34k_final_20261122.onnx` (3.83MB, 0.95M 파라미터, opset 17, SHA256 `9E87BDA4DEFBE301645896F3EA9C8CD15CBFB760FB41EFA46416ACCC794327EF`). 체크포인트 `unet_ch2_34k_final_20261122.pt`(`{'ch','sd'}`).
- ONNX 입력 `image` float32 `[1,3,h,w]`: RGB 0~1(평균 빼기 없음), 원본을 **0.5배 BOX 축소** 후 아래·오른쪽 reflect 패딩으로 **h,w를 16의 배수**로. 동적 축 h,w.
- 출력 `logits` `[1,1,h,w]`: sigmoid → 워터마크 확률. 패딩 부분 자름.
- 임계값 0.5(0.5/0.7/0.9 차이 1%p 이내). 후처리: 확률>0.5 픽셀이 12% 초과면 전면 무늬(이미지 전체 한 개), 아니면 6px 팽창→덩어리 라벨링→팽창 전 픽셀 30개 미만 제거→상자→좌표 ×2(`wm2/train/infer_eval.py`의 `boxes_from_mask`).
- 검증: PyTorch↔ORT 로짓 최대 차이 0.0005. 이 PC ORT CPU 약 74ms/장(512×368 입력). 폰 CPU 시간은 측정하지 않음.
- 더 높은 인식률이 우선이면 B(기존 합성기)가 core 91.8%/wild 80.5%지만 wild 음성 오인식 12.5%, ambiguous 43%라 권하지 않는다(체크포인트는 보관하지 않음, 필요하면 재현 가능).

## 4. 앱 통합 초안
1. ONNX를 `assets`에 넣고 ORT Android로 로드.
2. 페이지당 0.5배 축소 → 추론 → 상자 변환.
3. **방어 필수**: 낮은 정밀도(후보의 약 2/3가 오검출)를 전제로, 같은 사이트의 여러 장에서 **같은 위치·크기로 반복되는 상자만 워터마크로 채택**, 채택 후보는 사용자에게 보여 확인받기.
4. 전면 무늬(12% 규칙)는 오검출 위험이 있으니 별도 확인 단계.

## 5. 한계·미확인
- **실제 웹툰 미검증.** 학습·평가 모두 합성 만화+합성 워터마크.
- 폰 CPU 추론 시간 미측정. PC 글꼴 벤치라 폰 벤치(기준선 51.5%/99%)와 직접 비교 불가(PC 기준선은 73.3%/61.9%로 다름).
- 학습 도중 앱 재시작으로 20k 런 두 개가 6.6k 스텝에서 끊겨 6k 체크포인트부터 **이어서** 학습했다(학습률 스케줄을 새로 시작, seed 2). 완전한 20k 단일 실행과 약간 다르다. 이어 학습 때마다 옵티마이저 상태는 저장하지 않아 스케줄이 재시작된다.
- 큰 교사 모델·증류(핸드오프 단계 5)는 생략: 0.95M이 이미 앱 예산 안이라 필요성이 낮다고 판단.
- A와 B는 seed·스케줄이 같지 않아 합성기 효과만의 순수 비교는 아니다.
- val은 최종 후보 1회만 평가(개발 중 사용 안 함).

## 6. 폰 세션 할 일
1. ONNX 연결·한 장 추론 확인, 폰 CPU 시간 측정(0.5배 축소 360×~950 기준).
2. 독립 36장·실제 웹툰에서 상자를 눈으로 확인하고 오검출 양상 기록.
3. "여러 장 반복 위치 채택" 후처리를 얹어 실사용 정밀도를 측정.

## 7. 재현 명령
```
set PYTHONUTF8=1
python wm2/tools/gen_bench.py --tier core --out <bench> --jobs 10        # wild, val 도 동일
python wm2/train/build_pool.py --out <pool> --nbg 12000 --nspr 20000 --jobs 10
python wm2/train/pack_sprites.py <pool>
python wm2/train/train.py --pool <pool> --steps 20000 --bs 12 --workers 4 --device dml --ch 16,32,64,96,128 --synth synth2 --out <ckA>      # 실제로는 6k 후 끊겨 이어서 학습(--resume, --lr 8e-4 --seed 2)
python wm2/train/train.py --pool <pool> --steps 14000 --bs 12 --workers 4 --device dml --ch 16,32,64,96,128 --synth synth2 --lr 5e-4 --seed 11 --resume <ckA>/unet_14000.pt --out <ckFinal>
python wm2/train/eval_all.py <ckFinal>/unet_14000.pt --bench <bench> --tiers core,wild --ths 0.5,0.7,0.9 --tag x --device dml
python wm2/train/export_onnx.py <ckFinal>/unet_14000.pt out.onnx <이미지>
```
- 벤치는 PC 글꼴 대체표(`gen_bench.py`의 `_SUBST`) 사용. 학습은 AMD RX 6800 + torch-directml 0.2.5.
