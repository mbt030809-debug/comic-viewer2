# wm2 인식 파이프라인 시험판 (2026-11-24) — 예시 마크를 단색 여백에서 찾고, 그림 위에서 찾기

**중간 산출물이다.** 합성 테스트툰으로만 평가했고 실제 웹툰은 검증하지 않았다. 일부 평가는 아직 진행 중이라 표에 "측정 중"으로 표시했다(끝나면 갱신).
사양: `wm2/RECOGNITION_SPEC_20261123.md`(모양 분류·크기 범위). 방식 비교: `wm2/COMPARE_ABC_20261123.md`.

## 한눈에
입력 = 같은 사이트 이미지 3~8장(순서·위치 모름). 그중 한 장의 **단색(흰/검은) 여백**에 **예시 워터마크**가 있고, 다른 이미지의 **그림 위**에 같은 마크가 박혀 있다(불투명 중심, 반투명 포함, 위치·크기 매번 다름, 한 이미지에 여러 개/없음).
출력 = 어느 예시가 어느 이미지의 어디에 있는지 (예시 번호 + 상자).

```
1단계: 모든 이미지에서 '예시 후보' 찾기 (단색 여백 안의 마크)
2단계: 후보마다, 모든 이미지에서 찾기 (참조형 신경망 → 상자)
합의:  신경망 상자 중 템플릿 매칭(예시를 그대로 겹쳐 본 상관)도 같은 자리에서 확인한 것만 남김 → 말풍선·머리·눈 오검출 제거
확인:  후보가 자기 페이지 밖 이미지에서 발견될 때만 채택(캡션·쪽번호 후보 제거)
```

## 파일
| 파일 | 내용 |
|---|---|

| `wm2_ref_unet_25k_20261124.onnx` | 2단계 참조형 신경망(0.99M, 35k 스텝 누적). 4.0MB, opset 17. 입력 `image` [1,3,h,w] (위와 같은 전처리), `ref` [1,3,112,192] (예시 마크, 아래 참조) → 출력 `logits` [1,1,h,w] = '그 예시가 박힌 픽셀' 확률 |
| `pipeline_ref.py` | **기준 구현**(onnxruntime·numpy·pillow·scipy). 앱 이식 시 이 파일의 함수를 그대로 옮기면 된다 |

| `s2_tm.py` | 템플릿 매칭(마스크 정규화 상관, 0.5배 회색조, 크기 14단계) |

## 돌려 보기 (PC)
```
pip install onnxruntime numpy pillow scipy
python pipeline_ref.py sample/ref3_core_002 --s1net wm2_s1_unet_10k_20261124.onnx --s2net wm2_ref_unet_25k_20261124.onnx --s1 hybrid --consensus 0.5 --out out
```
`out/result.json` 에 `examples`(1단계가 찾은 예시: 이미지·상자)와 `detections`(이미지·예시 번호·상자·점수), `out/*_det.png` 에 그림이 저장된다.

## 설정(프리셋) — 정밀도와 재현율을 맞바꾼다
정밀도 = 표시한 상자 중 진짜 비율, 재현율 = 박힌 마크 중 찾은 비율.
| 프리셋 | 옵션 | 특징 |
|---|---|---|
| 정밀 우선(기본) | `--s1 hybrid --consensus 0.5` | 오검출 거의 없음(합성 8세트 시험: 정밀도 100%, 재현율 17%). 말풍선·머리·눈은 사실상 안 잡음 |
| 균형 | `--s1 rule --consensus 0.4 --also-tm 0.75` | core 재현율 35.9% / 정밀도 31.3%, val 39.5 / 36.4, 완전 새 벤치 36.2 / 41.6 |
| 신경망 위주 | `--s1 neural --consensus 0.4 --also-tm 0.75` | core 28.0 / 47.4, val 25.4 / 56.2, 완전 새 벤치 27.5 / 43.4 |
| 합의 없음(참고) | `--consensus 0 --s1 rule` | 재현율 52~54%, 정밀도 20~23%, 마크 없는 이미지 오검출 ~67% — 말풍선·머리 오인식이 많음 |
합의 0.5(추가 없음)의 core/val/새 벤치 전체 평가는 **측정 중**.
정답 예시를 그대로 준 경우(1단계 오차 제외, core 30세트): 합의 0.5 → 재현율 33%, 정밀도 93%, 마크 없는 이미지 오검출 1.4%.

## 2단계 입력 `ref` 만들기
1단계가 낸 예시 상자(x,y,w,h, 원본 해상도)를 사방 4px 넓혀 잘라, 0.5배 BOX 축소 → 112×192 캔버스(배경색으로 채움, 가운데 배치, 캔버스보다 크면 비율 유지로 더 축소)에 놓는다. 배경색 = 상자 바깥 6px 둘레 픽셀의 중앙값. 코드: `pipeline_ref.py` 의 `make_ref`, `page_bg`.

## 후처리 규칙(모두 `pipeline_ref.py` 에 있음)
- 확률 > 0.5 → 6px 팽창 → 덩어리 → 팽창 전 30픽셀 미만 제거 → 상자(좌표 ×2).
- 2단계 상자는 예시와 폭·높이가 0.6~1.75배 안에 있을 때만(머리카락·눈 조각 제외), 면적 ≤ 화면의 20%, 예시가 있던 자리 자체는 제외.
- 크기 사양(원본 해상도 기준, 이미지 폭 대비): 로고류 8~30%, 글자류 10~50%.

## 한계 (솔직하게)
- **합성 이미지로만 평가**. 새 벤치도 같은 생성기에서 시드·글꼴만 바꾼 것이다. 실제 웹툰은 검증하지 않았다(사용자 요청으로 실제 이미지는 쓰지 않음).
- 1단계가 병목: 학습형은 예시를 55~65%만 찾고, 규칙은 91~95% 찾지만 캡션·쪽번호가 많이 섞인다. 둘을 합친 hybrid 는 정밀하지만 재현율 약 50%.
- 참조형 2단계는 불투명 마크가 약하다(정답 예시를 줘도 재현율 51%, 반투명 81%). 템플릿 매칭이 일부 보강한다.
- 글자·URL·외곽선 글자, 캐릭터가 약하다. 회전·크기 비율이 예시의 0.7~1.4배를 벗어나면 약하다.
- **앱 이식 비용**: 신경망 2개 + 템플릿 매칭(FFT 상관) + 규칙(팽창·라벨링·구멍 메우기)이 필요하다. 폰 CPU 시간은 측정하지 않았다(이 PC에서 후보 1개 × 이미지 1장 = 신경망 약 0.17초, 템플릿 매칭은 이미지당 수 초). 처음 폰 시험은 `--s1 neural --consensus 0`(신경망 2개만, 말풍선 오검출 많음)으로 연결 확인만 하고 합의 단계를 이어 붙이는 순서를 권한다.
- 출력 정확도(IoU≥0.5, 예시 번호까지 같아야 맞음)는 합성 벤치 기준이며 임계값 0.5·상관 0.4~0.5는 합성으로 정했다.
