# wm2 시범용 모델: U-Net 0.95M, 10k 스텝 (2026-11-22)

**중간 산출물이다.** 같은 PC에서 20k+ 스텝 학습(하드 네거티브 합성기 포함)이 계속 돌고 있고, 끝나면 `RETURN_HANDOFF_*.md`로 최종 추천 모델을 따로 올린다. 이 모델은 "폰에서 ONNX 연결·시간 측정을 미리 해 보라"는 용도다.

## 1. 파일
| 파일 | 내용 |
|---|---|
| `wm2_unet_ch2_10k_20261122.onnx` | 3.83MB, opset 17, 사용자 정의 연산 없음(Conv·ConvTranspose·InstanceNorm·MaxPool·Pad 등). SHA256 `892E4650D12EB2A615284C07AEE713A1FB51BABB2B5446BD261969757FE8CAEB` |

## 2. 사용법 (ONNX)
- **입력** `image`: float32 `[1,3,h,w]`, RGB, 값 0~1(평균 빼기 없음). **h, w는 16의 배수**(동적 축). 원본 이미지를 **0.5배 축소(BOX/평균 방식)** 한 뒤, 16의 배수가 되도록 아래·오른쪽을 reflect 패딩한다.
- **출력** `logits`: `[1,1,h,w]`. `sigmoid`로 워터마크 확률 지도. 패딩 부분은 잘라낸다.
- **상자 변환**(`wm2/train/infer_eval.py`의 `boxes_from_mask`와 동일):
  1. 확률 > 0.5 이면 워터마크 픽셀.
  2. 그 픽셀이 지도의 12% 초과면 **전면 무늬**로 보고 이미지 전체 한 개를 돌려준다.
  3. 아니면 6픽셀 팽창 후 덩어리 라벨링, 팽창 전 픽셀이 30개 미만인 덩어리는 버리고, 덩어리마다 상자를 만든다. 좌표는 0.5배 축소 기준이므로 **2배**로 되돌린다.
- **임계값**: 0.5 권장. 0.5/0.7/0.9에서 인식률 차이가 1%p 이내라 크게 민감하지 않다(`rows_20261122.jsonl`).
- 검증: PyTorch와 ONNX 로짓 최대 차이 0.003(576×368 입력). 이 PC의 ORT CPU 추론은 약 131ms/장(0.5배 축소 576×368 기준). **폰 CPU 시간은 측정하지 않았다.**

## 3. 결과 (합성 벤치만, IoU≥0.5가 맞음, 임계값 0.5)
PC 글꼴로 만든 벤치라 폰 벤치(글꼴 다름)와 직접 비교할 수 없다. 같은 PC 벤치에서의 비교만 의미가 있다.

| 실험 | 파라미터 | 학습 | core 인식률 | core 음성 오인식 | wild 인식률 | wild 음성 오인식 |
|---|---|---|---|---|---|---|
| 기준선(폰 설정 재현) | 0.24M | 2.5k 스텝, 작은 풀 | 73.3% | 61.9% (78/126) | – | – |
| 3k 스텝 | 0.24M | 3k, 큰 풀 | 77.9% | 69.8% (88/126) | 69.4% | 87.5% (49/56) |
| 10k 스텝 | 0.24M | 10k, 큰 풀 | 84.9% | 17.5% (22/126) | 75.5% | 25.0% (14/56) |
| **이 모델: 채널 2배** | **0.95M** | **10k, 큰 풀** | **88.4%** | **7.9% (10/126)** | **77.5%** | **14.3% (8/56)** |
| 채널 4배 | 3.79M | 10k, 큰 풀 | 88.1% | 7.9% (10/126) | 77.2% | 14.3% (8/56) |

- 목표치(핸드오프 §6): core 인식률 ≥80% **달성**, 음성 이미지 오인식 ≤5% **미달**(7.9%), wild는 둘 다 미달. val은 최종 평가용으로 아직 보지 않았다.
- `ambiguous`(글자 든 고정 띠)는 오인식에 넣지 않고 따로 집계한다. 이 모델은 ambiguous에도 36.7% 상자를 낸다.
- **읽는 법**: 학습량을 3k→10k로 늘리자 오인식이 크게 내려갔다(69.8→17.5%). 채널 2배는 추가로 좋아졌지만 4배는 2배와 같다 → 10k 스텝에서는 용량이 아니라 학습량·문제 설정이 병목일 가능성이 크다. 오인식이 5% 아래로 가는지는 아직 모른다.
- 샘플 200개 반복 학습(1,500스텝, 0.24M)은 core 48%/오인식 78%로 일반화 확인용이 아니라 용량 진단용인데, 손실이 0.51에서 멈췄다. 스텝이 짧아 용량 부족 결론을 내기엔 이르다.

## 4. 한계 (솔직하게)
- **실제 웹툰으로는 시험하지 않았다.** 학습·평가 모두 합성 만화 + 합성 워터마크다. 분포 밖 성능은 모른다.
- 정밀도가 낮다(core 34%): 워터마크가 있는 이미지에서도 엉뚱한 상자를 많이 낸다(core 1,000개 안팎). 앱에 쓰려면 "여러 장에서 같은 위치·모양으로 반복되는 후보만 채택", 사용자 확인 같은 방어가 필요하다(핸드오프 §2·§5).
- 한 장 단독으로는 말풍선·글자와 글자형 워터마크를 구분하기 어렵다는 구조적 한계는 이 실험으로 해소되지 않았다.
- 학습 전 구간 DirectML(AMD RX 6800, torch-directml 0.2.5) 사용. 학습이 앱 재시작·PC 절전으로 한 번 끊겨 있다(이 모델의 10k 학습은 끊기지 않고 끝난 별도 실행).

## 5. 재현
```
set PYTHONUTF8=1
python wm2/tools/gen_bench.py --tier core --out <bench> --jobs 10        # wild, val 도 같은 방식
python wm2/train/build_pool.py --out <pool> --nbg 12000 --nspr 20000 --jobs 10
python wm2/train/pack_sprites.py <pool>                                  # 스프라이트를 메모리맵 파일로(워커 복사 방지)
python wm2/train/train.py --pool <pool> --steps 10000 --bs 12 --workers 10 --device dml --ch 16,32,64,96,128 --out <ckpt>
python wm2/train/eval_all.py <ckpt>/unet_10000.pt --bench <bench> --tiers core,wild --ths 0.5,0.7,0.9 --tag x --device dml
python wm2/train/export_onnx.py <ckpt>/unet_10000.pt out.onnx <검증용 이미지>
```
- PC 벤치는 글꼴 대체표(`gen_bench.py`의 `_SUBST`)로 Windows 글꼴을 쓴다. 폰 벤치와 이미지가 다르다.
- 학습 seed는 `train.py` 기본값(데이터 seed 1, torch seed 0).

## 6. 폰 세션이 해 볼 것
1. ONNX를 앱 `assets`에 넣고 ORT(Android)로 로드, 위 입출력으로 한 장 추론.
2. 0.5배 축소 이미지(360×~950)에서 **폰 CPU 시간 측정**(목표: 몇 초 이내).
3. 독립 36장·실제 웹툰 이미지에서 상자가 어떻게 나오는지 눈으로 확인(오인식 양상 기록).
